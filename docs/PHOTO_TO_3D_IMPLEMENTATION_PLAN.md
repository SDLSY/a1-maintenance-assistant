# Photo-to-3D 实现状态与落地路线

## 当前真实状态

当前系统尚未实现“上传照片后直接生成新的可测量 3D 网格”。已实现的是两类可演示能力：

- **one-photo**：上传单张故障图片后，系统提取图片语义标签，再映射到已授权的标准 3D 模型部件，完成部件高亮、SOP 定位和安全闸门提示。它是“照片到标准模型定位”，不是单图重建。
- **multi-photo**：上传多张照片后，系统执行质量门检查，生成离线重建任务包。它是“可交给 COLMAP / Meshroom / Nerfstudio 处理的任务包”，不是 Web 端实时重建。

这样设计的原因是：检修场景不能把未经校验的单图 3D 结果用于尺寸测量或安全放行。单图重建存在尺度不确定、遮挡幻觉、零件内腔不可见等问题；多图重建也需要足够角度、光照、纹理和人工验收。

## one-photo 算法路线

### v0 已实现：照片到标准模型定位

流程：

1. 上传图片并生成结构化视觉描述。
2. 提取设备、部件、缺陷标签和 OCR 文本。
3. 将标签映射到标准授权 CAD/GLB 的 `component_key`，例如 `outer_ring`、`rolling_elements`、`pump_seal_zone`。
4. 在 3D 工位中高亮对应部件，并同步 SOP 步骤、证据来源和安全检查项。

产出：

- 标准模型部件定位。
- SOP 空间绑定。
- 风险与证据链展示。

限制：

- 不生成新的 mesh。
- 不输出尺寸。
- 不作为安全放行依据。

### v1 可选增强：单图生成候选网格

可接入 TripoSR、Stable Fast 3D、CRM、LGM 或第三方 3D 生成 API，生成候选 GLB/OBJ，再与标准 CAD 做粗配准。

建议只把它作为“空间理解辅助层”：

- 生成结果必须叠加“实验性”标识。
- 必须和标准模型对齐后才能进入演示。
- 不进入主安全链路。
- 不参与验收尺寸测量。

## multi-photo 算法路线

### v0 已实现：质量门与离线任务包

流程：

1. 上传同一设备不同角度照片。
2. 检查照片数量、格式和重复文件名。
3. 生成 `scripts/run_3d_reconstruction.py` 的离线执行命令。
4. 记录支持的后端：COLMAP、Meshroom、Nerfstudio Splatfacto。

### v1 推荐实现：COLMAP / Meshroom 网格路线

流程：

1. 特征提取：SIFT/局部特征。
2. 特征匹配：相邻视角或全局匹配。
3. SfM 稀疏重建：求相机位姿和稀疏点云。
4. MVS 稠密重建：生成稠密点云。
5. 网格化：Poisson 或 Delaunay 网格。
6. 贴图与导出：输出 PLY/OBJ/GLB。
7. 人工验收：检查比例、孔洞、漂浮面、遮挡区域和关键部件。

适用场景：

- 表面纹理明显的设备外观。
- 拍摄角度充分、重叠度较高的照片集。

### v2 可选实现：Nerfstudio / 3D Gaussian Splatting 路线

流程：

1. 预处理图片并估计相机位姿。
2. 训练 NeRF 或 3DGS。
3. 导出可交互 splat 或提取 mesh。
4. 与标准 CAD 做空间对齐。

适用场景：

- 答辩展示更直观的空间浏览。
- 不要求精确可测量网格的视觉复原。

## 验收标准

- one-photo：必须能稳定定位到标准模型部件，并展示证据链、SOP 和安全限制。
- multi-photo：至少 12 张照片，覆盖 360 度或关键视角，质量门通过后才允许生成离线任务包。
- 真正重建结果：必须有依赖版本、执行日志、输出文件、人工质量验收和限制说明。
- 所有 3D 结果默认不参与尺寸测量和安全放行，除非通过额外计量校准和机械审核。

## 答辩表达

建议明确表述为：

> 本系统的主线不是把 AI 生成的 3D 当成检修依据，而是以授权标准 CAD/GLB 为可信底座。照片能力用于把故障现象映射到标准模型部件；多图重建作为离线增强能力，用于现场空间记录和辅助复盘。安全放行仍由 SOP、证据链和人工审核共同决定。
