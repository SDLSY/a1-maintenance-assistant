# Tri-MRO 三链对齐机制设计规格

日期：2026-05-14
状态：设计完成，待用户确认后进入实现阶段

## 目标

将现有 A1-MAKG 系统从“多模态 RAG + CAD + SOP 功能集合”收束为 **Tri-MRO：证据链-结构链-作业链三重对齐的可信检修平台**。

设计目标不是大改架构，而是在现有 FastAPI、前端、SQLite、CAD 工位和评测面板基础上增加一个统一机制，让评委能清楚看到：

- 故障判断有没有证据。
- 故障部位能不能落到 CAD/3D 部件。
- 维修建议能不能变成带安全闸门的作业票。
- 案例和人工修正能不能审核后沉淀。

## 设计选择

推荐方案：**轻量机制层叠加**。

不引入 Neo4j、不重写检索、不把 photo-to-3D 拉回主线。后端新增或扩展一个 `tri_mro_alignment` 聚合对象，由已有 `workflow_state`、`citations`、`spatial_guidance`、`sop_steps` 和 `compliance` 组成。前端新增三链状态卡和指标，不打断现有演示链路。

备选方案：

- 重型 GraphRAG/Neo4j：表达强，但当前时间风险高，部署和调试成本大。
- 只改答辩文案：成本低，但系统里看不到机制，容易被认为只是包装。

## 核心对象

`tri_mro_alignment`：

- `fault_claim`：关键故障判断。
- `evidence_chain`：手册、案例、图谱、图片、表格、页面截图证据。
- `structure_chain`：设备、`component_key`、CAD 模型、绑定等级、置信度。
- `operation_chain`：SOP 步骤、工具备件、验收标准、安全闸门。
- `safety_gate`：绿色可执行、黄色需确认、红色阻断。
- `knowledge_governance`：工单/案例状态、审核、版本、回滚。

## 页面设计

1. 检修任务台
   - 在生成方案结果顶部加入“三链对齐状态”。
   - 每个关键结论旁展示证据数量、CAD 部件、SOP 步骤和安全状态。

2. CAD 结构工位
   - 不再强调“3D 建模”，改成“结构链定位”。
   - 显示 CAD 绑定成熟度：语义热点、对象级绑定、CAD 面级绑定。

3. 证据链图谱
   - 默认展示当前任务子图，不展示全量乱图。
   - 路径形如：设备 -> 部件 -> 故障 -> 原因 -> 证据 -> SOP -> 安全项。

4. 案例沉淀
   - 从当前任务生成工单。
   - 审核前不入正式检索，审核后更新案例库、图谱和索引。

5. 评测与资源
   - 增加三链指标：三链对齐覆盖率、关键结论可追溯率、CAD 定位 Top-1/Top-3、高风险步骤阻断率、拒答合理率。

## 错误处理

- 证据不足：拒答或要求补充铭牌、清晰图片、设备型号。
- CAD 绑定不足：只展示候选部件，不自动放行，不声称面级测量。
- 安全条件不足：阻断高风险步骤，转人工确认。
- 云模型失败：使用本地检索、缓存视觉结果、规则 SOP 和安全规则兜底。

## 测试计划

- 4 条黄金链路：泵密封泄漏、电机轴承温升、轴承外圈剥落、发动机火花塞/压缩压力。
- 1 条反演示：证据不足 + 强行拆卸触发拒答/阻断。
- 指标回归：三链对齐覆盖率、关键结论可追溯率、CAD 定位准确率、安全阻断率。
- 浏览器 E2E：生成方案 -> 进入 CAD 工位 -> 返回诊断 -> 生成工单 -> 图谱/评测不丢状态。

## 实施边界

本设计不要求本轮直接实现核心代码。实现前应先确认：

- 用户认可 Tri-MRO 作为正式项目名称和答辩主线。
- 是否允许在 UI 中出现“语义热点绑定/对象级绑定/CAD 面级绑定”的成熟度说明。
- 是否暂时不把 photo-to-3D 放进主演示视频。
