# A1 答辩演示脚本

目标：用 8-10 分钟展示系统不是普通聊天机器人，而是覆盖“检索证据、标准作业、合规审查、知识沉淀、量化评测”的设备检修作业辅助系统。

## 演示前准备

```powershell
cd D:\30726\Desktop\竞赛目录\a1-maintenance-assistant
.\scripts\run_server.ps1
```

浏览器打开：

```text
http://127.0.0.1:8051
```

确认：

- 左侧模型供应商中 `codex` 和 `openrouter` 显示已配置。
- “资源与模型”页中向量检索为 `openrouter / qwen/qwen3-embedding-8b`。
- `docs/READINESS_AUDIT.md` 中公开资料、索引、模型路由、提交包均为 pass。

## 链路一：文本故障问诊

页面：问诊检修

输入：

```text
设备类型：电机
设备型号：Y2-160M
检修等级：二级检修
故障描述：电机运行 30 分钟后端盖温度升高，伴随低频振动和轴承异响。
```

点击“生成检修方案”。

讲解重点：

- 系统先按设备型号和故障语义召回手册与案例。
- 回答包含故障判断、可能原因、工具备件、步骤化 SOP、验收标准和风险等级。
- 引用区展示手册来源、页码、来源 URL 和许可说明，强调“证据可追溯”。

## 链路二：图片故障检索

页面：问诊检修

操作：

- 上传一张轴承剥落、油污、裂纹或泵体泄漏相关图片。
- 故障描述填写：

```text
请结合图片判断可能故障，并给出拆检前安全确认和作业步骤。
```

讲解重点：

- 视觉 Agent 先生成结构化 caption，再与文本、型号一起进入检索。
- 图片输入不是直接让模型猜，而是转成可追溯的检索条件。
- 如果现场没有图片，可使用本地规则 caption 兜底，系统仍可演示跨模态入口。

## 链路三：标准化作业与合规拦截

页面：问诊检修

输入：

```text
设备类型：离心泵
设备型号：ISG80-160
检修等级：三级检修
故障描述：泵出口压力波动，密封处持续滴漏，现场伴随异常噪声。
```

讲解重点：

- SOP 必须包含停机、断电挂牌、泄压/降温、PPE、防误启动、拆检、复装和试运行验收。
- 合规区会展示 LOTO、PPE、泄压降温、工具备件、验收标准等检查项。
- 规则引擎负责确定性安全项，LLM 负责复核和补充说明。

## 链路四：案例上传、审核与知识更新

页面：案例审核

输入示例：

```text
标题：现场新增：泵机械密封泄漏
设备型号：ISG80-160
故障现象：密封端面持续滴漏，停机后检查发现密封圈老化。
原因分析：机械密封老化，轴套表面磨损导致密封失效。
处置措施：断电挂牌并泄压后拆检密封组件，更换机械密封和 O 形圈，复装后试运行确认无泄漏。
```

操作：

- 点击“提交待审核”。
- 在待审核列表点击“通过审核”。
- 切换到“知识图谱”。

讲解重点：

- 未审核案例不会直接污染知识库。
- 审核通过后，案例进入案例库、检索索引和知识图谱。
- 这对应赛题要求中的“知识沉淀与更新”。

## 链路五：量化评测与提交准备

页面：评测面板、资源与模型

操作：

- 在“资源与模型”点击“快速评测”。
- 切换到“评测面板”查看对比指标。
- 打开 `docs/READINESS_AUDIT.md` 展示自动审计结果。

讲解重点：

- 对比“无 RAG / 文本 RAG / 多模态 RAG / 本系统”的 Recall@5、引用覆盖率、SOP 完整度、幻觉率和安全漏检率。
- 当前开发环境中案例和评测题已经达到数量要求，但正式参赛前需要机械专业队友把 `data/review` 审核包回写为 approved。
- LoongArch + 银河麒麟实机验证是最终提交前的必要证据，本机 Windows/AMD64 只能证明应用兼容性和本地完整链路。

## 收尾话术

本作品的核心不是“用大模型回答维修问题”，而是把设备检修流程做成可落地闭环：多模态输入、证据检索、标准作业、合规校验、人工审核、知识沉淀和量化评测。系统已经把电机、离心泵、轴承三类设备的公开手册、案例和评测纳入统一链路，后续接入企业私有手册或真实维修工单时，只需走同样的入库、审核和索引更新流程。
## 2026-05-11 演示补充

- 文本问诊完成后，先讲解 6 张 Agent 卡片：视觉、检索、机械诊断、SOP、合规审查、知识更新。重点展示每个 Agent 的输入、输出、证据、置信度和下一步动作。
- 量化评测环节先进入“资源与模型”，点击“四组对比评测”，再切换“评测面板”展示 `无 RAG / 文本 RAG / 多模态 RAG / 本系统` 四组真实计算指标。
- 若现场网络导致模型复核较慢，仍可演示对比评测，因为该评测走快速词法检索路径，不依赖远程 embedding。
