# A1 答辩追问与回答口径

## 1. 你们和普通维修聊天机器人有什么区别？

回答：普通聊天机器人主要给自然语言建议，我们的系统围绕检修作业闭环设计。用户输入文本、图片或型号后，系统先检索手册和案例证据，再生成故障判断、SOP、合规校验和知识沉淀动作。核心区别是证据可追溯、步骤可执行、更新有审核。

## 2. 多模态具体体现在哪里？

回答：一方面用户可以输入故障文本、故障图片和设备型号；另一方面手册中的图片、表格、流程图也会生成描述并绑定原始来源。图片输入不会直接生成结论，而是先生成结构化缺陷标签，再进入混合检索和证据验证。

## 3. 为什么只做电机、泵、轴承？

回答：这是主动收窄范围。A1 要求的是可落地的行业助手，如果一开始做成通用设备平台，很容易泛化空泛。电机、泵、轴承在工业现场覆盖率高，故障机理和检修流程也比较适合做 SOP 与评测。

## 4. 你们的数据从哪里来？

回答：当前使用公开维修手册、公开故障图片、团队整理案例和自建评测问答。每条数据都保留来源、页码或编号。后续如果接入企业数据，也会先经过审核和脱敏。

## 5. 如何避免大模型幻觉？

回答：系统不允许模型脱离证据直接回答。检索结果会返回手册来源、页码、案例编号和置信度；生成回答必须引用这些证据。低置信度或证据不足时，系统提示人工复核，而不是强行给结论。

## 6. Agent 编排是不是只是包装概念？

回答：不是。每个 Agent 对应一个工程职责和结构化输出，比如检索 Agent 输出证据列表，视觉 Agent 输出缺陷标签，SOP Agent 输出步骤和工具备件，合规 Agent 输出安全项检查结果。这些输出会被后续模块使用和校验。

## 7. 机械专业队友的价值体现在哪里？

回答：主要体现在设备范围选择、故障机理整理、SOP 步骤审核、安全合规规则、案例审核和评测打分。我们不是只做算法展示，而是把机械检修知识落实到作业流程和评分标准里。

## 8. 如果模型或 API 不稳定怎么办？

回答：架构上模型层可替换，文本模型、视觉模型、embedding 模型都通过配置切换。部署时应用、数据库、索引和案例库独立保留，即使模型切换，也不会丢失检索资产和知识沉淀结果。

## 9. 为什么还需要 Supabase？

回答：Supabase 用于在线部署场景下的数据持久化和同步，本地仍保留 SQLite 备份。这样既方便公网演示，也能保证比赛提交时数据可恢复。

## 10. 量化评测怎么做？

回答：计划至少比较无 RAG、文本 RAG、多模态 RAG 和本系统四组。指标包括 Recall@5、引用覆盖率、图片 Top-5 命中率、SOP 完整度、幻觉率和安全漏检率。最终答辩页必须使用真实跑数。

## 11. 知识图谱是不是过度设计？

回答：我们使用的是轻量关系模型，不上重型图数据库。图谱主要用于表达设备、部件、故障、原因、检查项、工具和案例之间的关系，服务于检索扩展和前端可视化。

## 12. 这个系统能不能真正落地？

回答：可以分阶段落地。第一阶段在公开数据和自建案例上完成检索、SOP、合规和审核闭环；第二阶段接入企业真实手册和检修记录；第三阶段结合现场工单系统和权限审核。当前作品重点证明第一阶段闭环可运行。

## 13. 国产化怎么考虑？

回答：系统架构支持两套模型配置：现有 API 配置用于快速开发和演示，国产模型配置可以切换到通义、智谱、DeepSeek、Qwen embedding 等。国产化部署本身可以作为加分项，但不能牺牲核心系统稳定性。

## 14. 如果评委说你们功能太多怎么办？

回答：可以把功能收束为一条主线：检修输入、证据检索、作业指引、安全合规、知识沉淀。其他模块都是为这条主线服务，不是无关功能堆叠。

## 15. 你们 PPT 里的评测结果为什么有 100%，可信吗？

回答：这不是第三方权威测试，也不代表系统在所有场景都没有错误。它表示在当前 104 道已审核评测题、当前设备范围和数据集内，检索与引用链路可以稳定命中。正式答辩时我会主动说明评测边界，并把后续扩展方向放在更难问题、噪声图片和现场工单数据上。

## 16. 机械专业审核到底做了什么？

回答：机械审核主要覆盖两类数据：125 条检修案例和 104 道评测题。审核项包括故障机理是否合理、SOP 步骤是否完整、安全合规项是否缺漏，reviewer 只用代号展示，避免把个人信息放进 PPT。

## 17. 公网部署有什么意义？

回答：公网部署证明作品不是只能在开发机上运行的脚本，而是具备在线演示、数据持久化和环境恢复能力。我们使用 Render 做在线服务、Supabase 做持久化，同时保留本地 SQLite 备份，答辩当天会准备公网和本地两套演示路径。

## 18. 如果现场网络不好怎么办？

回答：会提前准备本地演示环境、已生成的索引和数据库备份。模型调用如果不稳定，可以切换到备用模型配置；如果网络完全不可用，则用本地系统截图、演示视频和离线检索结果证明核心流程。
