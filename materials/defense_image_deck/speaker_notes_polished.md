# A1 全图版润色 PPT 逐页答辩讲稿

总体节奏建议：正式答辩控制在 8-10 分钟，演示另算 4-5 分钟。每页只讲一个结论，避免把页面上的所有字都念出来。第 15-18 页属于“证据页”，讲事实和来源，不要展开成新的功能介绍。

## 01 封面

讲法：我们做的是 A1 赛题中的多模态证据链作业辅助系统，目标不是做通用维修聊天机器人，而是面向电机、离心泵、轴承三类设备，形成“多模态输入、手册证据、SOP 合规、知识沉淀”的闭环。

强调：领域收窄、证据可追溯、作业可执行。

不要说：我们用了某某大模型所以先进。模型只是能力来源，不是作品价值本身。

## 02 检修现场痛点

讲法：现场检修的难点不是完全没有资料，而是资料分散、检索慢、流程不规范、老员工经验难以沉淀。我们的系统把这些问题统一到检修作业链路里解决。

强调：从“资料管理问题”升级为“检修执行问题”。

不要说：人工检修完全不行。应该说系统辅助一线人员降低检索和规范化成本。

## 03 A1 要求覆盖

讲法：这一页对应赛题原文。A1 要求可视化界面、多模态检索、标准化作业指引、知识沉淀更新，我们都给了明确系统模块和演示动作。

强调：先证明没有偏题，再讲创新。

不要说：全部覆盖所以一定能拿高奖。覆盖只是基础，后面还要证明做得扎实。

## 04 作业闭环

讲法：用户输入故障文本、图片或设备型号后，系统先检索手册和案例，再做故障判断，随后生成 SOP，合规 Agent 检查安全项，最后把人工审核后的案例沉淀回知识库。

强调：不是单轮问答，而是检修任务闭环。

不要说：模型直接给最终结论。要强调证据驱动和人工复核。

## 05 系统架构

讲法：前端是 PC Web 工作台，后端用 FastAPI 编排检索、Agent 和数据更新。知识库和索引在本地保留，Supabase 做持久化同步，模型能力通过云端 API 接入。

强调：应用层可部署，模型层可替换，数据层可恢复。

不要说：必须依赖某一个国外模型。要说架构支持国产模型和中转模型切换。

## 06 数据资产与证据追溯

讲法：当前数据包括公开手册、人工整理案例、故障图片、评测问答和向量索引。所有回答要求带来源、页码或案例编号，低置信度时提示人工复核。

强调：这是降低幻觉的核心机制。

不要说：这些数据已经覆盖所有设备。要说我们聚焦三类设备，先做窄领域高质量闭环。

## 07 多模态混合检索

讲法：图片不会直接交给大模型自由发挥，而是先通过视觉模型生成结构化 caption，比如裂纹、油污、剥落、泄漏痕迹，再与文本检索、向量检索、型号过滤、图谱扩展结合。

强调：多模态的价值在于提高召回证据的准确性。

不要说：图片识别一定准确。要说图片结果会回到证据库验证。

## 08 多 Agent 协同

讲法：我们把大模型拆成多个岗位：检索 Agent 找证据，视觉 Agent 处理图片，诊断 Agent 给原因排序，SOP Agent 生成步骤，合规 Agent 检查安全项，更新 Agent 负责知识沉淀。

强调：分工让系统更可控、可检查、可解释。

不要说：Agent 越多越好。要说每个 Agent 对应明确工程职责。

## 09 SOP 与安全合规

讲法：这一页是机械专业参与最强的地方。系统输出不是泛泛建议，而是包含断电挂牌、PPE、能量释放、工具备件、拆检步骤、复装验收的结构化 SOP。

强调：安全合规是区别于普通 RAG 的关键。

不要说：系统可以替代检修负责人签字。要说系统辅助提醒和规范作业，关键步骤仍需人工确认。

## 10 知识沉淀闭环

讲法：一线人员上传案例后，系统先抽取设备、故障、原因、措施和经验总结，进入待审核状态；审核通过后再写入案例库、知识图谱和检索索引。

强调：知识更新有审核门槛，避免错误经验污染知识库。

不要说：所有上传内容自动进入知识库。一定要强调审核。

## 11 量化评测

讲法：评测页不是为了堆指标，而是证明系统比无 RAG、文本 RAG、多模态 RAG 更稳。最终版需要展示 Recall@5、引用覆盖率、图片 Top-5、SOP 完整度和安全漏检率。

强调：现在页面应替换为真实实验结果，不伪造数值。

不要说：目前目标值就是实测值。答辩前必须确认真实跑数。

## 12 答辩演示路线

讲法：演示按五步走：文本问诊、图片检索、SOP 生成、合规拦截、案例审核更新。每一步只证明一个能力，避免现场自由发挥导致不稳定。

强调：演示要短、稳、可复现。

不要说：可以现场随便问。正式答辩建议使用准备好的脚本输入。

## 13 部署与提交准备

讲法：当前部署路线是 Render 在线演示、Supabase 持久化、本地 SQLite 备份。提交前重点是冷启动、数据恢复、环境变量、评测报告和演示视频都可复现。

强调：工程稳定性比额外堆功能更重要。

不要说：国产化部署已经完全完成，除非有真实环境截图和测试记录。

## 14 核心创新点

讲法：最后总结六个点：领域垂直、证据可追溯、多模态检索、机械 SOP、知识闭环、量化评测。我们的价值不是模型更大，而是把多模态大模型落到了检修现场的证据链、作业链和知识链。

强调：用一句话收束，让评委记住差异点。

不要说：功能很多。要说每个功能都服务于 A1 的检修闭环。

## 15 真实系统演示截图

讲法：这一页把前面所有概念落到真实系统界面。五张截图分别对应文本问诊、图片检索、SOP 生成、合规校验和案例审核，正好覆盖 A1 的多模态检索、作业指引和知识更新要求。

强调：截图来自本地可运行系统，不是 gpt-image-2 概念图；正式答辩前可替换为公网部署截图。

不要说：界面已经最终定稿。可以说这是当前可运行版本，后续前端重构只优化交互和视觉，不改变核心链路。

## 16 当前自动评测结果

讲法：这页展示 104 道已审核评测题上的自动对比结果。无 RAG 作为反例，本系统和 RAG 方案在当前评测集上都能命中证据和引用，说明基础检索链路已经跑通。

强调：这是项目内部自动评测，不包装成第三方权威测试；评委如果追问，主动说明评测集规模、来源和审核状态。

不要说：100% 代表系统没有问题。要说当前评测集偏向已知设备范围，后续会继续加入更难问题和现场噪声数据。

## 17 机械专业审核摘要

讲法：这一页证明机械专业不是挂名参与。案例库和评测题都经过 reviewer 代号审核，并对故障机理、SOP 完整度和安全合规做了 5 分制评分。

强调：分数不是满分，这反而说明我们保留了真实审核意见；SOP 完整度仍是后续打磨重点。

不要说：机械审核已经完全替代真实现场验证。应说这是比赛阶段的专业复核机制，真实落地还需要企业现场流程确认。

## 18 公网部署验证

讲法：最后一页说明系统可以公网访问，Render 服务健康检查正常，Supabase 已启用，提交前还会再跑冷启动和核心流程验证。

强调：这是工程可用性的证据，不是单纯本地 demo；同时保留 SQLite 备份，避免在线服务异常导致数据不可恢复。

不要说：部署已经永久稳定。云服务免费或低配环境可能冷启动，正式答辩前必须提前预热并准备本地备用方案。
